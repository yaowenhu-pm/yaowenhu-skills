# elegant-docs · 优雅文档写作

## 原则

文档的目的是传递信息，不是展示写作量。每一句话都应该是读者需要的。

**数字约束**（基于阅读心理学研究）：


| 维度     | 约束                         | 依据                 |
| ---------- | ------------------------------ | ---------------------- |
| 全文字数 | ≤ 900 字                    | 超出后留存率显著下降 |
| 主要章节 | 3–5 个                      | Miller 定律（5±2）  |
| 每段字数 | ≤ 100 字，3–5 句           | 超出读者跳过         |
| 平均句长 | 中文 ≤ 35 字，英文 ≤ 20 词 | 理解成本临界点       |
| 列表项数 | ≤ 7 项，优先 ≤ 5 项        | 同上                 |
| 信息位置 | 结论前置                     | F 型阅读模式         |
| 比较内容 | 3+ 项用表格，不用段落        | 表格扫描比文字快 4× |

超出 900 字时，强制精简——裁冗余，不截断。

## 禁忌

- 套话开头：不写"本文将介绍……"、"随着 XX 的快速发展……"
- 重复表意：同一件事只说一次
- 填充词：不用"显而易见"、"众所周知"、"值得注意的是"
- 结尾总结：读者刚读完，不需要重复

## 工作流

**模式 A：从零写作**

若用户未提供，先问两个问题：

1. 读者是谁？
2. 这份文档一句话的目的是什么？

得到答案后，按原则起草并直接输出。

**模式 B：润色草稿**

1. 内部诊断（不输出）：字数、段数、最长句、是否有可表格化内容
2. 按原则重写
3. 末尾一行简评：改了什么，为什么

## 格式选择

- **表格**：比较、对照、参数列表
- **列表**：步骤、枚举（无需展开说明时）
- **段落**：有逻辑关系、需要语境的内容
- **代码块**：命令、路径、示例值

能用表格就不用段落，能用列表就不用长句。
