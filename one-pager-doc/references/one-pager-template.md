# 产品 one-pager 填写模板

复制下方骨架，用实际材料替换尖括号内容。缺少关键资料时写“待确认”或“当前假设”，不要把提示语原样留在成稿中。采用用户指定格式时可以调整结构。

```markdown
# <产品名>｜产品 one-pager

<版本> · <更新日期> · <阶段或本轮目的>

| 主题 | 当前表述 |
| --- | --- |
| 使命 | <希望长期改善的结果；关键抽象词的具体含义> |
| 用户与场景 | <首个用户群、任务与使用场景；适用时区分验收／决策者与付费者；首版范围> |
| 定位与价值 | <现有做法和痛点；产品交付的成果；成果如何用于后续动作；标明价值假设> |
| 长期方向 | <验证成立后的方向，与首版范围区分> |
| 阶段目标 | <日期或触发条件：验证对象、样本／交付、验收条件；拟议项明确标注> |
| 成功标准 | <有效使用的定义；完成、采用与再次使用如何记录；关键质量／效率指标及口径> |
| 产品与体验原则 | <与核心任务相关、能指导具体取舍的少量原则> |
| 当前进展 | 截至 <事实核对截止日期>：<已完成项与证据；当前产物状态及未验证部分> |
| 当前最大未决 | <一个最影响下一步的主问题；确认后改变的范围或验证动作> |

依据：<确实读取过的资料及链接；公开版仅使用获准公开的依据>
```

阶段目标与成功标准应连起来，例如：

> **阶段目标（拟）：**在双方确认的试用期内，用获授权的真实任务验证成果能否进入用户的后续流程；样本数量与期限待确认。
>
> **成功标准：**预先约定的成果经过使用者检查并用于下一步才计为采用；分别记录尝试、完成、采用、再次使用、关键错漏与含复核的总耗时。

这只是工作任务产品的写法示例，不替代具体产品的验收条件，也不提供固定的数量、比例或时间门槛。
