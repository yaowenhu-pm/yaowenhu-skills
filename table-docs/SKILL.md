# table-docs · 三列表格文档

产出文档的正文主体**固定使用**「类型 | 事项 | 说明」三列表格，不用章节标题 + 段落的传统结构。

**只转换结构，不改写文字。** 这个 skill 的任务是把原文的信息装进三列表格里，原文怎么表达就怎么搬——不精简、不润色、不改措辞、不加不减信息。原文的每一句话、每一个数字、每一个链接都要能在表格里找到对应位置。如果同时需要润色内容，那是 elegant-docs 的工作，先润色再表格化，两步分开。

## 固定结构

1. **引言**（2–3 行）：文档目的 + 遇到问题找谁
2. **主体表格**：「类型 | 事项 | 说明」
3. **补充说明**（可选，≤ 3 行）：注意事项、生效时间等，不写车轱辘总结

```markdown
| 类型 | 事项 | 说明 |
| ---- | ---- | ---- |
| 准备工作 | 办公室门锁 | 地点：XXX，密码：XXX |
| 准备工作 | 连接 WiFi | 名称：XXX，密码：XXX |
| 账号权限 | 申请邮箱 | 找 XX 开通，格式：name@example.com |
```

## 三列规则

- **类型**：从原文已有的章节标题/分类词里取（如原文写"准备工作"就用"准备工作"，不新造词）；是天然的分组轴，同一类型连续多行，类型名重复写（渲染到飞书等平台后再做单元格合并）
- **事项**：原文里这一行说的是什么事/什么对象，直接取原文用词或原文的小标题，不概括、不精简成新短语；一行一件事，原文顺序即表格顺序
- **说明**：原文对这件事的具体描述，原样保留——句子、数字、链接、人名、步骤都不改；原文本来是换行/分点的，保持换行/分点；原文是一整句的，就整句放进说明列，不拆不减

## 原文已有表格的处理

按原表结构分三种情况，单元格内容一律原样保留：

- **原表就是（或接近）三列结构**：直接并入主表格。列名对得上就直接搬；原表只有两列（如"事项 | 说明"）的，类型列从原表所在章节的标题取
- **原表列结构不同**（对比矩阵、参数表、多维数据表等）：**不拆**。原表作为独立表格整体保留，放在主表格之后；主表格中在对应位置加一行，事项写原表标题（或原文对它的称呼），说明写"见下方表格：XXX"
- **原表是嵌入组件丢了内容**（如飞书粘贴出的"暂时无法在文档外展示此内容"）：在主表格对应位置保留占位行，说明写"〔原文嵌入表格，迁移时补〕"，不得凭上下文脑补表格内容

## 边界

- 表格前后只放原文已有的、无法归入某个"事项"的内容（如开场问候语、结尾备注），照抄原文，不改写
- 原文有信息在表格三列都放不下（如一大段叙述背景），整段原样放进最近一行的说明列，或作为单独一行放进引言/补充说明区——不得因为"不好归类"而删减
- 只做结构搬运，不做二次创作；如果原文本身冗长、口语化、有语病，保持原样，不在此步骤修正
